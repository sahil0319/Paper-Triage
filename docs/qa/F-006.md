## Findings
### F-007 [FE] low: new-search scope reset is not announced
`render()` calls `resetChat()` but does not append the "Chat now covers N papers" sentence to `#status`; `#status` reads "1 paper ranked. Results below." `#chat-note` has no `aria-live`/`role`. The load-more path does append it. A screen-reader user is not told that the chat scope and transcript changed after a new search. Expected (task brief): note in `#chat-note` and `#status`.
Repro: serve with `MOCK_LLM=1` on 8766; search "diffusion distillation"; search "2401.00001"; read `#status` text: "1 paper ranked. Results below." and `#chat-note` has no live-region attributes.
Fix hint: in `render()` append the sentence returned by `resetChat()` to `statusEl.textContent` when the note is shown. The e2e spec `test_new_search_clears_chat_transcript` only checks `#chat-note`; add a `#status` assertion.

### F-008 [FE] low: Ask stays disabled after a reset while a stale reply is in flight
`resetChat()` -> `refreshChat()` sets `askBtn.disabled = empty || chatBusy`, and `chatBusy` stays true until the dropped request settles (`askInto` final `.then`). After load-more or a new search the user cannot ask about the new scope until the old request finishes (up to the LLM latency), and Enter in `#question` is a silent no-op (`if (askBtn.disabled || chatBusy) return`). Observed: with a held reply, `#ask` disabled after the reset; enabled again once the stale reply returned.
Repro: search; ask a question and hold `/api/chat` (Playwright route or slow model); click `#load-more`; `#ask` is disabled with no explanation.
Fix hint: on reset set `chatBusy = false` (the stale `.then` already guards on `gen`, but must then not re-enable/disable by its own `chatBusy = false` for a newer request: key it to `gen === chatGen`).

### Note, not logged (pre-existing)
The count in the note and scope line counts non-failed rows (`okCount()`), while `paper_ids` carries all shown rows including failed ones. With failed rows the sentence reads lower than the ids sent. Cosmetic; backend ignores failed papers.
